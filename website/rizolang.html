Rizo Lang

Security, built into the language.

Describe your data, who may do what, and your pages in a short .rz file. Rizo Lang compiles it into a PostgreSQL database, a Node.js and TypeScript server, and web pages, with security built in rather than bolted on.

$npx rizolang build app.rz

Open source (Apache 2.0)On npm as rizolangVersion 0.6.0
blog.rz (excerpt)auth User by email roles admin, editor

model User {
  email: Email unique private
  password: Password min 12
  name: Text max 100
}

model Post {
  author: User
  title: Text min 1 max 200
  body: Text
  published: Bool
}

api DELETE /api/posts/:id {
  requires login
  requires owner author or role admin
  return db.Post.delete(id)
}

page /posts/new {
  requires login
  title "Write a post"
  form POST /api/posts
  then go /posts/:id
}

Why it's different

Most frameworks make security possible. Rizo Lang makes the common mistakes impossible to write, which matters most when an AI model is doing the writing.

01

Dangerous mistakes are impossible, not just unlikely

There's no way to write raw SQL, so SQL injection can't happen. Pages contain no HTML, so cross-site scripting can't happen. Passwords are always hashed and can never be returned.

02

Built for AI

The whole language fits in a short spec that any AI model, even a small one, can learn from. Every error says what went wrong, the exact line and column, and how to fix it.

03

Small and strict

Strong types, one clear way to do each thing, and no runtime of its own. It compiles to technology you already know: PostgreSQL, Node.js and TypeScript.

What you get from one .rz file

A complete, hardened back end and front end, generated as readable code you own. The only runtime dependency is pg.

Data and APIs

Models compiled to a PostgreSQL schema with constraints, plus TypeScript types. Endpoints where access is part of the syntax: public, requires login, requires role admin, requires owner author.

Lists and migrations

Paginated lists with search and filters, automatic database indexes, and safe migrations that refuse to delete data unless you say so.

Web pages

Pages and forms generated from your endpoints, with no HTML to write and a strict Content Security Policy. Apps with accounts get login and signup pages and a menu.

Accounts, built in

Signup with email confirmation, login, password reset and passkeys (fingerprint, face or device PIN). Signup never reveals which emails already have accounts.

Sessions

A device list and "log out everywhere". Only a hash of each session token is stored, in HttpOnly, Secure cookies.

Encrypted fields

Mark a field encrypted and it's encrypted with AES-256-GCM before it reaches the database, with key rotation.

Hardened by default

Every endpoint is rate-limited, every query has a time limit, and cross-site requests are blocked.

Audit log

Logins, failed and blocked logins, password and role changes, deletions and token use are recorded, with no secrets, for admins to review.

Ready for AI agents

API tokens that work only on the endpoints you choose, expire within 90 days and can never change the account. Plus an openapi.json with every access rule.

Tools for agents

rizolang build --json returns errors as JSON for agents to fix, and rizolang audit reviews your app for risky choices and suggests fixes.

What the compiler writes

Everything lands in dist/ as ordinary files. Read them, review them, deploy them wherever Node.js runs.

FileWhat it is
schema.sqlThe PostgreSQL schema, with constraints and indexes
types.tsTypeScript types for every model, its public view and its input
routes.tsEvery endpoint, with its SQL written out in full and its access checks
server.tsA ready-to-run Node.js server with login, validation and pages
openapi.jsonAn OpenAPI 3.1 description of every endpoint and its access rules
migrate.ts, migrations/Numbered migrations, each applied in a transaction with checksums
runtime/The page renderer and browser client
DockerfileA small production image: Node.js 24 on Alpine, only pg, a non-root user and a health check

The security model

These guarantees hold for every app Rizo Lang builds, and they're checked by a dedicated security test suite and end-to-end tests against a real database.

No injection

All SQL is written by the compiler. Requests can only fill in parameters, never change a query.

Access is mandatory

Every endpoint must say who may call it. Ownership is checked inside the query itself, so other people's records simply aren't found.

Passwords done right

Hashed with scrypt and a random salt, with a minimum length you can only raise. Password and private fields are never returned.

No cross-site tricks

SameSite cookies, JSON-only bodies and origin checks on every write. Pages get a strict CSP and can't be framed.

Abuse limits

Rate limits on every endpoint, a 5-second limit on every query, and required email confirmation.

Quiet logs

Request logs record only method, route, status, time and request id. Nothing personal, nothing secret.

Privacy rules for the regions you serve

Declare where your users are, and the app is generated to help with the technical side of those laws.

blog.rz (excerpt)auth User by email roles admin, editor

// People can download and delete their data on /account.
privacy for EU, UK, IN, US-CA, BR

model Comment {
  post: Post
  author: User
  body: Text min 1 max 2000
  keep 5 years
}
  • Covers GDPR, UK GDPR, India's DPDP Act, California's CCPA and Brazil's LGPD.
  • Users can download all their data and delete their account from their account page.
  • keep 5 years deletes a model's records that long after they were created.
  • A privacy page is generated from your actual models. No cookie banner is needed, because generated apps don't track.
  • These features help with the technical parts of privacy laws. They aren't legal advice.

Get started

You need Node.js 22.12 or newer (24 LTS recommended) and PostgreSQL 13 or newer.

# Compile your app
npx rizolang build app.rz

# Install, migrate and run what it generated
cd dist
npm install
export DATABASE_URL=postgres://user:pass@localhost:5432/app
node migrate.ts
RIZO_PUBLIC_URL=http://localhost:3000 RIZO_EMAIL_DEV=1 node server.ts

Or do it all in one command: DATABASE_URL=... npx rizolang dev app.rz builds, migrates, starts on localhost:3000 and restarts when you save. With RIZO_EMAIL_DEV=1 the server prints confirmation emails instead of sending them. In production, set RIZO_EMAIL_API_KEY and RIZO_EMAIL_FROM. The README covers every setting, and the language spec covers every feature.

Everyday app features: search and filters, an account page, one command to run your app locally, and the basics for deploying it.

shop.rz (from the 0.6.0 release notes)model Product {
  name: Text max 100
  priceCents: Number min 0
  launched: Date
}

api GET /api/products -> list Product.public {
  public
  return db.Product.list(name contains ?q,
    priceCents >= ?min, priceCents <= ?max,
    order priceCents)
}

Search and filters

List filters can use !=, <, <=, >, >= and case-insensitive contains. ?name is an optional query parameter, so /api/products?q=mug&min=1000 just works and a filter left out is skipped. Values never become part of the SQL.

Account page

/account lets people edit their profile, change their password, and change their login email, confirmed by a link to the new address. The old address is told about the change.

rizolang dev

One command builds, migrates and runs your app on localhost:3000. Save the file and it restarts; a mistake shows its fix while the app keeps running.

Ready to deploy

A /_rizo/health check for hosting platforms, graceful shutdown on redeploy, and a generated Dockerfile: Node.js 24 on Alpine, a non-root user and a built-in health check.
