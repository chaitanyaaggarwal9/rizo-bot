Rizo Lang · Compiles to PostgreSQL + TypeScript

The common web security mistakes can't be written.

Rizo Lang is a small, strict language for web backends. You describe your models, login and endpoints in one .rz file, and the compiler generates the database schema, the types and a Node.js server. There's no raw SQL, passwords are hashed and never returned, and every endpoint has to say who may call it.

Get started View on GitHub
npx rizolang build app.rz

Early development (v0.3). Expect the language to change before 1.0.

app.rz// a small blog
auth User by email

model User {
  email: Email unique private
  password: Password min 12
  name: Text max 100
}

model Post {
  author: User
  title: Text min 1 max 200
  body: Text
  published: Bool
}

api GET /posts -> list Post.public {
  public
  return db.Post.list(published = true, order title, limit 20)
}

api PATCH /posts/:id -> Post.public {
  requires login
  requires owner author
  return db.Post.update(id, body)
}
Why

Designed so the mistakes don't compile

Most web security bugs are ordinary mistakes: a query built from text, a password returned in a response, an endpoint that forgot to check who is calling, a user editing someone else's data. Rizo Lang doesn't just warn about them. It has no way to write them.

Secure by default

Passwords are hashed and never returned. Input is validated automatically. Login and ownership checks are part of the syntax, not something to remember.

No raw SQL

Every query is generated at compile time and parameterized. The generated routes file shows the full SQL for each endpoint, so you can review exactly what runs.

Small and strict

Static types everywhere, and the whole language fits in a short spec. Every error gives the file, line and column, and says how to fix it.

Built for AI

The compact spec is under 1,500 words and works as a system prompt, so even small models can write correct Rizo Lang. Each error's fix: line is something a model can apply directly.

Output

Compiles to technology you already use

rizolang build app.rz writes everything to dist/. The only runtime is a small, readable library copied into your project, and the only dependency is the pg driver.

FileWhat it is
schema.sqlPostgreSQL tables with NOT NULL, UNIQUE, CHECK and foreign-key constraints, plus the sessions table
types.tsTypeScript types: User (server-only), UserPublic (safe to return) and UserInput (what clients send)
routes.tsEvery endpoint as plain data, with its SQL written out in full
server.tsThe entry point: node server.ts
runtime/Validation, sessions, password hashing and the HTTP server
migrate.tsApplies your project's migrations to the database
Security model

Every guarantee is tested against a real server

The end-to-end suite attacks a generated server backed by PostgreSQL. Found a hole? Report it privately.

ThreatHow Rizo Lang prevents it
SQL injectionAll SQL is written at compile time. Request data only fills $1, $2, … parameters.
Leaking passwordsPassword and private fields are never selected for responses.
Weak passwordsscrypt with a random salt, and a minimum length you can only raise.
Missing login checksEvery endpoint must declare public or requires login.
Editing others' datarequires owner becomes part of the SQL WHERE clause. Owners are set from the session.
Mass assignmentUnknown body fields are rejected. Ownership links are never accepted from clients.
Privilege escalationRoles are never accepted from requests, and admins can't assign roles to themselves.
CSRFSameSite=Lax cookies, JSON-only bodies and an Origin check on every write.
Brute forceRate limits on login and signup, and identical responses for unknown accounts and wrong passwords.
Accidental data lossMigrations that would drop data are refused unless you pass --allow-data-loss.
Errors

Errors that tell you the fix

Every error has a code, an exact location and a concrete fix. If a build has errors, no files are written.

app.rz:14:5 error RZ0318: Endpoint "GET /posts" does not say who may call it.
  14 | api GET /posts -> list Post.public {
     |     ^^^
  fix: Add `requires login` for logged-in users only,
       or `public` if anyone may call it.

app.rz:20:18 error RZ0326: "Post.author" links to the auth
model, so the server must set it.
  20 |   return db.Post.create(body)
     |                  ^^^^^^
  fix: Write `db.Post.create(body, author = me)`.

Build failed with 2 errors. No files were written.
Get started

From one file to a running server

01

Write app.rzModels, login and endpoints, like the example at the top of this page.

02

npx rizolang build app.rzCompiles everything into dist/. Or add it to a project with npm install --save-dev rizolang.

03

cd dist && npm installInstalls pg, the only dependency.

04

node migrate.ts && node server.tsWith DATABASE_URL pointing at your PostgreSQL database.

Requirements

  • Node.js 22.12+ to run the compiler. The generated server needs 22.18+; Node 24 LTS is recommended.
  • PostgreSQL 13+
  • The full spec and the compact spec for AI models
  • Open source under the Apache License 2.0
